title: A file from the RAM disk
command: cat /init.rc
show: sh, memrofsd, registry
note: fs/1 Open ("ocamlrun" | To start a program, its parent first reads the program's file through the file service, then hands it to the kernel. Here trace reads ocamlrun, the OCaml runtime, to start sh.
note: spawn of sh | A process is born: the kernel makes it from the file its parent read, with its own memory. It is ocamlrun, and it will run sh.byte.
note: fs/1 Open ("sh.byte" | The new process reads its program, sh.byte, from the RAM disk: the same service, the same requests as any other file.
note: registry/1 Lookup | Before talking to a service, a process asks the registry for its port: the registry is the one service everybody can find, at a fixed port.
note: fs/1 Open ("init.rc" | Now cat itself: sh asks memrofs to open init.rc. A message, through the kernel, to another process; the answer is a number, the file descriptor.
note: fs/1 Read | A read is a request and a reply: up to 16 KB of the file travel back in the reply's message.
note: fs/1 Close | Done: the descriptor goes back to memrofs.
note: exit of sh | sh ends: the kernel frees its memory, its ports and channels, and tells its parent.

In MyNOS a file is not something the kernel knows about. It is what a service gives you over IPC: fs/1, a typed protocol that every file service speaks and describes.

/ is the RAM disk, served by memrofs, a process written in C in 2002. This lesson watches sh start and then ask memrofs for init.rc, the file that tells init what to start at boot.

Look at the arrows: every one goes down into the kernel and up again. The kernel carries the messages; it does not read the file.

title: A directory from the disk
command: ls /disk
show: sh, fatfs, ata, registry
note: Lookup "fatfs" | sh needs the file service of the disk: it asks the registry for fatfs's port.
note: block/1 Read | fatfs does not touch the disk: it asks the driver, ata, for sectors. This call is made while fatfs serves sh's: a call inside a call.
note: fs/1 List | sh asks fatfs for the directory's entries: one typed request, and all of them come back in the reply, names and sizes.
note: fs/1 Open | sh asks fatfs to open a file; fatfs finds it in the directory, which it may first have to read from the disk.

/disk is a FAT disk, kept across boots. Between sh and the disk stand two processes, both written in OCaml: fatfs, the file system, and ata, the driver that talks to the disk controller.

Run this lesson twice. The second time, fatfs answers from its cache, and ata is not asked at all: the arrows to ata are gone.

title: A program is born
command: hello
show: sh, hello, memrofsd, tmpfs
note: spawn of hello | sh asks the kernel for a new process. The kernel loads the program its parent has read, ocamlrun, and starts it with its arguments: hello.byte.
note: fs/1 Open ("hello.byte" | Before starting it, sh looks at the file: a native program, or OCaml bytecode? It reads its first bytes. Bytecode is run by ocamlrun, the OCaml runtime.
note: hello( | The newborn process is ocamlrun: it now reads its program, hello.byte, from the RAM disk, through memrofs, like any file.
note: fs/1 Write | hello greets. Its output goes where sh told it to: here, a file of /tmp, served by tmpfs (the tour keeps the output); in a terminal, the console.
note: exit of hello | hello ends: the kernel frees what it held and wakes sh, which was waiting for it.

Every program in MyNOS is a process, started by another one. A program written in OCaml is a process of ocamlrun, the OCaml runtime, which runs its bytecode.

This lesson watches sh start hello, the smallest program there is: born, it reads itself, writes one line, and ends.

title: Over the network
command: ping 10.0.2.2 2
show: sh, netd, registry
note: Lookup "net" | sh looks up the network service in the registry.
note: IRQ 9 | The network card interrupts. The kernel does not handle the packet: it wakes netd's thread, and netd reads the card itself. This arrow comes from the hardware.
note: net/1 | sh speaks to netd with typed requests: net/1, a protocol that describes itself. Each request is an OCaml value, carried in a message.

netd is the network service: a driver for the NE2000 card and a TCP/IP stack (lwIP), in one process written in C. Programs ask it for sockets, names and packets.

This lesson pings the host (10.0.2.2, QEMU's gateway) twice: watch the requests go to netd, and the card's interrupts come back up from the hardware.

title: Asking a language model
command: llm What is a microkernel? Answer in one sentence.
show: llm, llmd, netd, fatfs, registry
note: llm/1 Chat | llm asks llmd, the model service (OCaml), with a typed request: the conversation, as an OCaml value.
note: fs/1 Open ("llm.env" | llmd reads its configuration from the disk: which provider, which model, which key.
note: net/1 Connect | llmd opens a connection to the provider through netd: TLS runs inside netd.
note: net/1 Send | The request goes out, as JSON over HTTPS.
note: net/1 Recv | The answer comes back, a piece at a time.
note: IRQ 9 | Packets arrive: the card interrupts, netd wakes.

A language model is a service of MyNOS like the others: llmd speaks to the providers configured in /disk/llm.env (see llm.env.example), and programs ask it over typed IPC. The agent works the same way, with tools.

It needs a model configured; without one, the lesson shows llmd's answer that there is none.

title: A service that dies
command: kill fatfs; ls /disk
show: sh, fatfs, init, registry, ata
note: registry/1 List | To end a service by its name, sh asks the registry for every name and the process that registered it. fatfs, the disk's file system, is a process like any other, with a pid.
note: exit of fatfs | The kernel ends fatfs. It frees what fatfs held, its memory, its ports and channels, and tells whoever was waiting on them. Nothing else stops: the file system was only a program.
note: spawn of fatfs | init started fatfs at boot, and watches it: it sees it end, and starts it again. A new process, with a new pid.
note: block/1 Read | The new fatfs reads the disk through ata: it starts from what is on the disk, not from what the old one had in memory.
note: Register "fatfs" | The new fatfs registers the name fatfs again: a new port, under the old name.
note: Lookup "fatfs" | ls needs the disk, but the port sh knew for fatfs is gone: sh asks the registry for the name again. Not found, yet: init is starting the new fatfs. sh asks again, a few times, until the new one has registered.
note: fs/1 List | The directory comes back, from the new fatfs. sh never knew which process answered: only the name.

In a monolithic kernel the file system is part of the kernel: if it fails, the machine stops. In MyNOS it is a process, written in OCaml, that other processes find by name in the registry.

This lesson kills fatfs and then lists the disk. Watch init start a new fatfs, the new one register its name again, and sh find it by name as if nothing had happened.
