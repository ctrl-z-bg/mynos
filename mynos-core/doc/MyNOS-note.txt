---------------
A bit of theory
---------------

We assume to be in protected mode with A20 enabled.

386 Memory Management (from: "Intel 386 programmer's manual" - chapter 5)
---------------------

There are 3 layers of memory addresses:

a) logical  address
b) linear   address
c) physical address

a) a logical address is given by a segment and a relative offset.
   Adding the offset to the segment base you obtain an address in the
   0-4GB range, called "linear address".

b) the linear address, 32 bits, is handled by the processor in this
   manner: the upper 10 bits are an index in a table, called the "page
   directory", one per process, which lets the processor access another
   table, a "page table", up to 1024 per process, where the next 10
   bits of the linear address identify another entry which points to a
   physical page ("page frame"). The last 12 bits are used as
   offset inside the page frame (of size 2^12 = 4096 bytes).
   So 1024 page tables x 1024 page frames * 4KB = 4GB, the full address
   space.

3) the physical address is calculated with a segment translation and a
   2-level hierarchy page translation (as described above). That is, each
   entry in the page table is the physical address of a page. The entire
   page directory/page table tree occupies at most 1024+1 = 1025 pages,
   that is, 4Mb plus 4Kb.


Segments and Pages
------------------

Every process has at least 2 segments: code and data. In their simpler
form they can lie on the full linear space: 0-4 GB.
A segment has many information for management and security purposes
(see: "Intel 386 programmer's manual" - chapter 6).
The most important fields are BASE and OFFSET.
There is a table (GDT - Global Descriptor Table), accessible by every
process, which contains the segment descriptors. In addition to it, a
process can have its own table with its own segment descriptors (LDT -
Local Descriptor Table).
Both GDT and LDTs can have up to 8192 8-bytes entry. The first gdt
entry is not used by processor, so you can use it as a null
descriptor.


386+ TSS ("Intel 386 programmer's manual" - chapter 7)
--------

Intel 386+ (and clones) have support for multitasking. You should
create a per-process TSS (Task State Segment). A tss is a structure
that holds all the informations the processor needs in order to manage
a task (registers image, LDT selector, page directory address and
more).
At the end of the required fields, we can add the OS specific process
informations.
For each tss you should add a special segment descriptor to the gdt:
the TSSD (Task State Segment Descriptor), which treats the tss like a
segment.
A task switch occurs in 4 cases (see: "Intel 386 programmer's manual" -
paragraph 7.5), the one we are interested in is when there's a jump to
a tssd.
A nice 386+ feature is that when the system switches to a task with a
page directory pointer different from the current one's, the processor
itself flushes and invalidates the memory page cache.


Interrupts and Exceptions ("Intel 386 programmer's manual" - chapter 9)
-------------------------

When an interrupt or an exception occurs, the system activates an
interrupt/exception handler. Such an entity can be a routine running
in the current process space, or another task (by task switch). We are
interested in the former case.
The interrupts can be Maskable or Nonmaskable.
The exceptions can be processor detected (faults, traps and aborts) or
programmed (software interrupts generated by istructions like 'int').
There is a table, called IDT (Interrupt Descriptor Table), which can
hold up to 256 8-bytes entries, where the Nth entry points to the
handler for the Nth interrupt.
The first 32 interrupt identifiers are reserved.
To avoid a task switch everytime an interrupt or an exception
occurs, we can use an 'interrupt gate' or a 'trap gate', which are
special kinds of entry in the gdt, pointing to the routine logical
address. The main difference between interrupt gate and trap gate is
that the former disables the interrupts (IF bit of EFLAGS register)
automatically while the latter does not.
If the interrupt is sent by PIC (Programmable Interrupt Controller)
the routine must send it an EOI (End Of Interrupt: 0x20 to the port
0x20).
The last interrupt/trap routine instruction must be 'iret', and not
'ret' like for "normal" routines.
Note that 'iret' restores the IF (Interrupt Flag) to the value it had
before the interrupt occured.


------------------
MyNOS architecture 
------------------

MyNOS is based on a microkernel (MyNOS-core). 
MyNOS-core will manage processes and kernel threads (creation,
destruction, scheduling), IPC (Inter Process Communication) and pages
(allocation, deallocation).
We'll refer to it sometimes with MyNOS too, when the term is not
ambiguous. In general, when we refer to the very low level operating
system stuff, we are referring to MyNOS-core.

Every process has its own page directory. The first 256 page directory
entries (the first GB of linear memory) are aliased for all processes;
this means that every process has the same first GB of linear
memory: this is the kernel space.
We need this because the kernel is not a process itself (we could do
it, but it's not a good idea to have a task switch every kernel mode
switch). Instead, the kernel is the group of routines called by
hardware interrupts and by system calls. This way, the kernel has
the same linear space of the current process, so it can access its
data (very useful for the patameters of a system call).
The kernel runs in the space of the current process, and we need a
trick to let the kernel access its own code and data, without strange
memory translations. To achieve this goal the first GB of each process'
linear space is aliased to the same physical space.
The code, data, stack, heap, ecc. of a new process is above this space,
starting from linear address 1GB.

The kernel needs to access the memory structure of the current process,
so we chose to map it this way:

- the last page directory entry is used to map the current process' page
  tables.
- the last entry of the last page table of the last but one page
  directory is used to map the page directory itself.
- the last but one page frame of the last page table of the last but one page
  directory entry is used as process stack (for now 4KB of stack are ok :)

Better seen on this diagram.

  PD                                            1022nd PT
+----+                                           +----+
|  0 |...                                        |... |
|... |...                                        |1022|-- STACK
|1022+-------------------------------------------+1023|-- points to PD
|    |                                           +----+
|1023+---+ points to the process page tables
+----+   |...
         |...
         +---

On new process creation its code and data are loaded starting from 1GB
of linear memory (above the kernel linear memory space).

A bitmap is used to track the physical memory pages (allocated or
not).



-------------
MyNOS startup
-------------

MyNOS-core is multiboot compliant
(http://www.mcc.ac.uk/grub/multiboot_toc.html) so we can use GRUB
(http://www.gnu.org/software/grub/grub.en.html) as the bootloader.

When the bootloader leaves the system control to the kernel (with
interrupt disabled), it does several things:

- enable paging
- create the page structure defined above
- initialize the physical memory bitmap
- set our true gdt (before we started with a simple one created by
  grub)
- initialize the PIC (Programmable Interrupt Controller)
- create our IDT (Interrupt Descriptor Table)
- initialize the PIT (Programmable Interval Timer)


------------------------------
MyNOS interrupt and trap gates
------------------------------

The 16 (see some pic documentation) hardware IRQ signaled by PIC are
mapped from interrupt 32 to interrupt 48.
There are two macros, ISR_WRAPPER and TRAP_WRAPPER, that can be used
to declare both interrupt or trap handler. The difference is that the
ISR_WRAPPER macro sends the EOI to the PIC.
Let's suppose you want to create a new interrupt (or trap) service
routine. You must do three things:

1 - ISR_WRAPPER(AbCd); // or TRAP_WRAPPER(AbCd);
2 - write the function void AbCd_handler()
2 - set_vector(AbCd_ISR /* or AbCd_TRAP */, intNumber, FLAGS)
    where FLAGS could be D_PRESENT, and D_INT if you want your routine
    not-interruptable.


----------------
MyNOS main files
----------------

- start.asm
  is the entry point of MyNOS-core. It enables the paging and jump to
  the mynos_main function (main.c).

- main.c
  it owns the mynos_main function, the real kernel 'main' function.

- mem.[hc]
  several macros are defined to manage the current process linear
  memory space (pages) and the global physical pages bitmap. Pages
  allocation/deallocation functions are defined too.

- gdt.[hc]
  gdt management stuff (init, add entry, ...).

- io.[hc]
  basic In/Out from/To a port

- pic.[hc]
  Programmable Interrupt Controller code.

- pit.[hc]
  Programmable Interval Timer code.

- idt.[hc]
  Interrupt Descriptor Table management code (including ISR_WRAPPER,
  TRAP_WRAPPER and set_vector).

- kutils.[hc]
  some useful functions.

- global.h
  general settings.

- dynalloc.[hc]
  kmalloc/kfree implementation.

- tss.h
  the tss structure (with some MyNOS-core specific information).

- video.[hc]
  basic screen printing functions (printk, ...).

- process.[hc]
  process creation/termination code.

- 3parts directory
  it contains some files taken from other systems, and put there for
  temporary tests.
